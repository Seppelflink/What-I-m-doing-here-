# Module 10 — Operations and Maintenance

Overview
- Learn what to do after an AI feature is released: monitor it, respond to issues, update it, and plan recovery.
- Practice using privacy-conscious operational signals and a simple incident runbook.
- The exercise uses a fictional service and synthetic events; no deployed app or real user data is needed.

Learning objectives
- Choose useful service, quality, and safety signals to monitor
- Triage an incident, limit impact, communicate clearly, and record follow-up work
- Plan dependency, provider, and model changes with regression checks
- Define backups, restore tests, ownership, and a regular maintenance cadence

Prerequisites
- Modules 08–09 are recommended (secure development; testing and releasing)
- No API key or cloud service is required

Structure
- slides.md — monitoring, incident response, updates, and recovery
- exercise.md — triage a fictional AI service incident and create an operations runbook
- assets/incident-scenario.md — synthetic service timeline and events
- assets/sample-runbook.md — one possible operational response

Estimated duration: 45–60 minutes
