# Module 02 — Prompt engineering

Duration: 40 minutes
Level: Beginner → Intermediate

# Slide 1 — Why prompts matter
Prompts shape model behavior: clarity, constraints, and examples change output quality.

# Slide 2 — Be specific
Specify the task, desired format, length, and tone.

# Slide 3 — Provide context
Add necessary background or domain details. Prefer including the minimum viable context.

# Slide 4 — Use examples (few-shot)
Show 1–3 examples in the prompt to demonstrate the expected output format or style.

# Slide 5 — Control randomness
Explain temperature/creativity settings (when available) and ask for deterministic formats if needed.

# Slide 6 — Ask for structure
Request JSON, bullet lists, or numbered steps for machine-parseable output.

# Slide 7 — Iteration workflow
Draft → Run → Inspect → Refine. Keep a log of prompt versions and outputs.

# Slide 8 — Evaluation
Check for accuracy, relevance, bias, and safety. Use automated checks where possible.

# Slide 9 — Common patterns
- Instruction + constraints
- Few-shot examples
- Step-by-step decomposition

# Slide 10 — Examples
- Instruction-only: "Summarize in one sentence: <text>"
- Few-shot: provide 2 examples then "Now summarize: <text>"
- Structured: "Return JSON with keys 'summary' and 'keywords'"

# Slide 11 — Tips
- Avoid sensitive data in prompts
- Start narrow, then broaden
- Prefer explicit formatting requests
